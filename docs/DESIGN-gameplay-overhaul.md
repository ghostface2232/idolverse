# 게임플레이 오버홀 설계 — "대응"에서 "설계"로

작성일: 2026-08-02. 근거: 레퍼런스 게임 심층 조사(프린세스 메이커 2, Game Dev Story, Football Manager, 우마무스메, 몬스터팜, Idol Manager, 스타듀밸리, Punch Club, Two Point Hospital, CK3) + 현행 코드베이스 전수 분석.

---

## 1. 진단 — 현행 구조의 4가지 결함

1. **수동적 루프.** `processWeek`의 플레이어 입력은 `PlayerDecisions = {trainingSchedule, resolvedDecisions[], promotionOrders?}` 3개 필드뿐. 파이프라인 3~13단계는 플레이어를 다시 참조하지 않는다. 결정 카드는 위기 대응(부상·재계약·투자자 압박)이 대부분이라 "설계"가 아닌 "대처"다.
2. **컴백 사이클의 공백.** 16주 사이클에 능동 선택 4개(무드/장르·센터·예산티어·타이틀곡). 앨범 제작 진행(`progressAlbum`)은 완전 자동. MV·마케팅·파트 분배·발매 타이밍은 선택지가 없다. GUIDE.md에 기획된 "MV 제작 티어", "바이럴 마케팅/광고 캠페인"은 코드에 존재하지 않는다.
3. **이벤트 = 플레이버.** `RANDOM_EVENT_POOL` 45개 중 다수가 선택지 없는 확인 모달 + 평면 스탯 델타. 잔존 결과(dormant consequence)가 없어 사건이 기억되지 않는다.
4. **런 간 차별화 부족.** 분기 요소는 투자자 5종·오디션 규모·컨셉 순서 정도. 상호배타적 전략 축, 시장을 읽고 베팅하는 구조가 없다.

## 2. 레퍼런스에서 가져올 원칙 (요약)

- **우마무스메**: 모든 위험한 선택에 **가시적 확률/기대치**를 붙여 플레이어가 도박을 "선택"하게 한다. 이벤트 풀은 플레이어의 빌드가 구성한다.
- **GDS × FM**: 메소 사이클의 클라이맥스는 **느리고 단계적인 공개** + **진행 중 개입 가능성**. 결과표가 아니라 시퀀스.
- **Punch Club × GDS**: 큰 순간은 "불확실성 아래 세운 **준비 가설**의 검증"이어야 한다. 노이즈 섞인 시장 예보를 읽고 컨셉을 베팅 → 결과에서 **요인별 어트리뷰션**("트렌드 적중 +18%, 라이벌 동주차 −11%")으로 학습.
- **CK3**: 이벤트는 선택지 + 트레이드오프 + **잔존 결과**(최악의 타이밍에 터지는 잠복 플래그).
- **Idol Manager 반면교사**: 센터/파트 분배의 질투 경제는 이 장르 고유의 결정 공간 — 플레이버가 아닌 실질 결과를 가져야 한다.
- **FM**: 성공하면 기대치가 올라가 같은 성적이 "하락세"로 읽히는 기대치 인플레이션이 오토파일럿을 막는다.

## 3. 이번 오버홀 범위 (Phase 1)

컴백 사이클을 "4개 선택의 16주 대기"에서 "**설계 → 베팅 → 검증**"의 능동 루프로 재구축한다.

### 3.1 시장 예보와 컨셉 베팅 (Punch Club/GDS 원칙)
- `ComebackPlanningModal`에 **다음 분기 트렌드 예보**를 노출: 현재 핫/콜드 장르·무드 + 다음 시즌 예측(노이즈 포함, 적중률 ~70%).
- 라이벌 컴백 캘린더를 계획 화면에 함께 노출해 발매 주차 경합을 미리 읽게 한다.
- 데이터: `calendarStore.marketTrend` + `upcomingCompetitorComebacks` 재활용. 예보 생성은 `calendarSystem`에 순수 함수 추가.

### 3.2 MV 제작 방향 선택 (신규 결정 스테이지)
- 컴백 `teaser` 스테이지에 `mvDirection` 결정 추가 (`decisionStatuses` 패턴).
- 3방향 × 예산 연동: **퍼포먼스 집중**(albumChoreography/방송점수↑), **시네마틱 세계관**(albumVisual/코어팬덤↑, 고비용·고분산), **글로벌 트렌드형**(global/유튜브↑, 국내 임팩트↓).
- 각 옵션에 멤버 적합(센터 비주얼/댄스 스탯)과 기대 효과·리스크를 가시화.

### 3.3 마케팅 캠페인 설계 (신규 결정 스테이지)
- `pre-reaction` 스테이지에 `marketingPlan` 결정 추가: 한정 예산 포인트를 **4채널**(SNS 바이럴 / 방송 푸시 / 팬덤 화력 / 글로벌 플랫폼)에 배분.
- 각 채널은 4축 팬덤의 다른 축과 차트 컴포넌트에 기여. 배분 자체가 전략 선언이 된다.
- 발매 정산에서 채널별 성과를 어트리뷰션으로 회수.

### 3.4 파트/푸시 분배 실질화 (Idol Manager 원칙)
- 기존 `comeback-part-assignment` 이벤트를 **실제 결정 모달**로 승격: 푸시 멤버 2인 선택 + 분배 기조(에이스 집중/균등 분배) 선택.
- 결과: 푸시 멤버 개인 인기·컨셉 성과↑, 소외 멤버 만족도↓(트레잇에 따라 가중). 집중이 반복되면 불만 누적 — 잔존 결과.

### 3.5 발매 정산 어트리뷰션 (GDS 니어미스 원칙)
- `evaluateRelease`가 이미 계산하는 요인(시너지 등급, 시즌 적합, 트렌드 스윙, 라이벌 경합, MV/마케팅 기여)을 **정산 리포트에 요인별 분해**로 노출.
- 아깝게 진 순위는 "다음에 당길 레버"를 명시한다.

## 4. Phase 2 (같은 업데이트에서 구현 완료)
- **훈련 푸시-유어-럭**: 강도별 부상 위험 배율(`INJURY_INTENSITY_MULT` 1×/2.5×/5×) + 돌파 급성장(`TRAINING_BREAKTHROUGH` 8%/15%). 확률을 훈련 UI에 그대로 노출 — 강훈련이 매주 살아 있는 도박 선택이 된다.
- **잠복 플래그**: 이벤트 선택(`EventChoice.flag`)이 `dormantFlags`로 남고, 매주 굴려지다 컴백 발매·활동기 창에서 5배 배율로 격발(`DORMANT_FLAG`). 열애 제보 묵인·건강 권고 은폐 2종 + 격발 템플릿.
- **인터루드 운영 활동**: 비활동기 주간에도 예능·자컨·라이브·멤버십 이벤트를 주 1건 실행(`listInterludePromotions`) — "조용한 주"가 능동적 운영 주간이 된다.
- **활동기 긴급 개입**: 차트 추이를 보고 당기는 레버 2종 — 팬덤 총공(음방 팬투표 +14), 스트리밍 스퍼트(주간 차트 감쇠 ×0.35). `ACTIVITY_INTERVENTION`.

## 4.5 Phase 3+ (후속 제안)
- 기대치 티어(1위 후 같은 성적이 "하락세"로 평가) — FM식 기대치 인플레이션.
- 세대교체/재계약 절벽, 유닛/데뷔조 선발, 엔딩 매트릭스.
- 데뷔 앨범 컨셉 선택(현재 하드코딩) 개방, 발매 타이밍 지연 결정.

## 5. 구현 규칙
- 모든 수치는 `src/data/balance.ts`. 신규 효과 키는 `EffectKey` + `applyEffects` + `effectKeyContract.test.ts`.
- 신규 결정은 `decisionStatuses` + `components/dashboard/` 모달 + `weekRunner`의 `completeXAndSave` 패턴.
- Phaser는 로직 무보유 원칙 유지.
